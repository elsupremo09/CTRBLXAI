=== [SUPERSEDE 2026-10-15] MULTI-MODEL + MULTI-FACE AD BILLBOARD (USER DECISIONS 2026-10-15) ===
This supersedes the single-fixed-model wording above (which itself superseded the 2026-10-12 strip model). All prior wording is retained above as [SUPERSEDED] history; nothing is deleted. "At most one Ad Billboard per map," placed on the center-nearest eligible SINGLE OBS tile, is UNCHANGED, as are all obstacle properties (one tile; impassable; BlocksLoS; immovable; unbreakable; elevation-immune; non-landable).

MODEL POOL BY NAME-PREFIX: The billboard MODEL ASSET is drawn from a pool of ALL Models whose NAME STARTS WITH "Billboard" (per existing normalizeName casing), located in ServerStorage > "Map Objects" (or ServerStorage root). The OLD exact-name lookups "Old Roblox Billboard" and "Ad Billboard" are DROPPED as the model-asset lookup rule; only the "Billboard" name-prefix counts now. Note: an asset literally named "Ad Billboard" no longer matches (it starts with "Ad", not "Billboard") — if the user wants that asset in the pool it must be renamed to a "Billboard" prefix. The internal ObjectData / obstacle TYPE KEY remains "Ad Billboard" (unchanged) — only the MODEL ASSET lookup changed.

SEEDED RANDOM PICK: When a map places its single Ad Billboard, the specific model is chosen at RANDOM from the prefix pool, SEEDED by the map seed, so the same map always shows the same model. The pick MUST be deterministic per seed and MUST NOT perturb existing map-gen RNG determinism / obsFormRng draw ordering (implementation: a dedicated or derived seed stream, or a draw ordered so existing layout/forms are byte-identical for the same seed). Requirement: same seed => same map layout AND same billboard model as today's single-tile behavior, with only the model-asset identity varying.

MULTI-FACE AD SURFACES (OPTION A — FIXED FACES): Each billboard model may contain 1..N flat panel Parts named "AdFace1", "AdFace2", ... ("AdFace" + integer). EACH such Part is a STATIC ad surface carrying the placeholder decal now and a real Roblox immersive ad later; all AdFace# parts update together. A model with NO AdFace# part still works as an obstacle but has no ad surface. Fixed faces are used specifically for angle visibility while remaining eligible for live immersive ads.

NEVER CLICKABLE: The billboard must NEVER be clickable/tappable in battle. Our code attaches NO ClickDetector and NO GUI button to the billboard or its AdFace parts; the placeholder decal is display-only. This holds for the live-ad phase too: ad surfaces remain display-only as far as our code is concerned.
