KEY DECISIONS (avoid re-looking these up)

==========================

- All skills scale with equipped main weapon + optionally a primary stat. No weapon/spell distinction.

- Perk/drawback mutation: any unit can mutate via authored events (battlefield Mutator, dungeon events, etc.). Always swap, never remove. Every unit has exactly 1 perk and 1 drawback.
- 2H weapon equipped → Armor Off-Hand WT = 0.

- Focus weapons: architecturally supported, excluded from initial implementation.

- Inventory: no hard cap. Maintenance cost past a threshold (soft economic pressure).

- AI per-unit budget: 50-100ms. 3-tier funnel (filter → score → preview). Role-based complexity.

- Map pre-generation: 4 maps after each battle while player is in menu.

- Event queue hard cap: 128 per action. Yield every 32 events.

- Save data: compact numeric IDs + lookup tables. Split across 3 DataStore keys.

- All game logic: server-side only. Client displays and sends commands.

- Deterministic: same seed + same content version = same result. No random variance in combat.

--- PERSISTENT HP/MP SYSTEM (added 2026-08-26) ---



persistent_hp_mp_rules (25 rows)

  HP and MP persist between battles. No auto-refill. Post-battle recovery, KO penalty, MP Regen, base rules, max changes, passive interactions, deployment UI.

  Key formulas:

    Post-battle recovery: ceil(Max HP x 0.35) and ceil(Max MP x 0.35) for all surviving units

    MP Regen: 6 x Total INT / (200 + Total INT) MP per 1000 CT (accumulator-based, CT-elapsed)

    KO: zero recovery, cleared only at base

    Base: replenishes Item charges but does NOT restore HP/MP

  Query: SELECT section, topic, rule FROM persistent_hp_mp_rules WHERE section = 'X'

  Sections: Persistent Resources, Post-Battle Recovery, KO Rules, Natural MP Regen, Recovery Stalling, Base Rules, Max Resource Changes, Passive Interactions, Deployment UI, Starter Support
